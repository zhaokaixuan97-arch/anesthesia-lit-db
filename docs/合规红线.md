# 合规红线

本库面向科室内部使用，但它是**联网的、可复制的、会留下历史记录**的。以下规则请务必遵守。

## 一、结论先行

**已发表的文献和指南本身没有患者隐私问题**——它们是公开出版物。这个库真正的风险来自两处：

1. **版权**：付费文献的 PDF 全文再分发属于侵权风险。
2. **你自己附加的内容**：顺手写进去的病例细节、未发表数据、患者信息。

所以规则很简单：**"文献层"可以放，"患者层"和"未发表层"永远不进这个库。**

## 二、能不能放：逐项对照

| 内容 | 判定 | 说明 |
|---|---|---|
| 文献题录（标题、作者、期刊、年份、DOI、PMID） | ✅ 放心放 | 公开事实信息 |
| 期刊公开摘要 | ✅ 放心放 | 公开信息 |
| 你自己写的 PICO、结论、点评 | ✅ 放心放 | 前提是**不含患者细节** |
| 学会指南的要点摘录 | ✅ 内部可用 | 大段复制原文要谨慎 |
| 开放获取（OA）文献的链接 | ✅ 放心放 | |
| 开放获取（OA）文献的 PDF 文件 | ⚠️ 可以但没必要 | 建议只存链接，避免仓库膨胀 |
| 付费文献的 PDF 全文 | ❌ 不要提交 | 版权风险；放对象存储或只存链接 |
| 病例摘要、手术记录、麻醉记录单 | ❌ 绝对不行 | |
| 随访表、原始研究数据 | ❌ 绝对不行 | |
| 病例图片、监护截图、超声图像 | ❌ 绝对不行 | 常含姓名/住院号水印 |
| 伦理审批材料、知情同意书 | ❌ 绝对不行 | 含患者签名与身份信息 |
| 未发表数据、在投稿件、审稿意见 | ❌ 绝对不行 | 影响发表与评审 |
| 基金申请书、标书 | ❌ 绝对不行 | |
| 排班表、成员手机号、邮箱列表 | ❌ 没必要 | 不属于文献库范畴 |
| 厂商报价、采购合同 | ❌ 绝对不行 | 商业敏感 |

## 三、一条判断标准

> **"这段内容我能不能直接贴到期刊上或公开网页上？"**
> 能 → 可以进库。不能 → 不要进库。

## 四、去标识化不等于安全

即使去掉姓名，以下组合也可能反推出个人身份：

- 罕见病 + 手术日期 + 医院名称
- 年龄 + 性别 + 特殊术式 + 时间
- 住院号后几位、床号、影像编号

**不要以为"去掉了名字就没事"。** 患者层面的任何信息一律不进库。

## 五、技术防线

1. **提交前自动扫描**：`python scripts/validate.py` 会扫描疑似住院号、身份证号、手机号、患者姓名标注、未发表数据等，命中严重项会拒绝通过。
2. **GitHub Actions 强制校验**：每次 push / PR 都会跑一遍，不通过就标红。
3. **`.gitignore` 兜底**：`*.pdf`、`exports/`、`.env` 等默认不提交。
4. **本仓库目前是 public**（为了用 GitHub Pages 免费托管检索网页）。
   这意味着：**任何 push 上来的内容，几秒钟后对全网可见，搜索引擎也可能收录。**
   所以 push 之前**必须先跑** `python scripts/validate.py`，确认隐私体检没有红线告警。

> 自动扫描是**辅助**，不是保险。它只能发现明显模式，最终责任在录入人。

## 六、账号与权限

翻车通常发生在这些地方：

| 风险 | 做法 |
|---|---|
| 误把仓库设成 public | 本仓库已是有意公开（见第五节第 4 条），但**其他仓库**建好后要立刻确认可见性 |
| 邀请错人 / 成员离职未移除 | 用 **Organization** 而非个人账号；每季度复核成员 |
| Token 泄露 | 用细粒度 PAT，限定单仓库 + 短有效期；不要写进脚本 |
| 用个人账号建库 | 人一走库就失联；一律用组织账号 |

## 七、万一误提交了敏感内容

**删除文件是不够的**，Git 历史里还在。必须：

1. 立刻把仓库改为 private 或暂停协作者访问
2. 用 `git filter-repo` 或 BFG 清理历史，然后强制推送
3. 联系 GitHub Support 请求清除缓存（公开仓库尤其重要）
4. 在科室内部登记事件

所以最好的处理方式是**一开始就不要提交**。
